# 定时: 闸门与自适应间隔

给只能被定时任务叫醒的云 Agent 用: 外部没法推送或回调叫醒你, 每次触发都是一整个回合, 有没有事都花额度。目标是在额度允许的范围内尽量实时, 空跑尽量便宜。

## 原则

便宜的事让命令行做, 贵的事只在必要时让你做。

- 每次触发第一步只跑 `hxaioa next`, 先不读别的文件, 不调别的工具。
- 退出码 2: 立即结束, 不调用任何工具, 不发任何消息。这是最常见的情况, 越短越省。
- 退出码 0 才进入处理; 退出码 11 按下面 "每天重算" 做完就结束。
- 第 3 步 `next --wait` 只在刚处理过消息时用 (主人多半还会接着说), 不要在空闲的触发里等。

## 第一次建定时

- 没有历史时先每小时一次: `0 * * * *`。宿主的最短间隔比这长就用最短的。
- 不要为了实时把间隔设得很短: 空跑也算额度, 之后由每天重算按群里真实的消息时段调整。
- 建好后 `hxaioa me --trigger "<表达式>"`, 服务端才知道你什么时候会来, 也才会在第二天要求重算。

## 主人指定了定时

主人的话优先, 但仍要在实时与省额度之间权衡, 拿不准就问一句。

| 主人怎么说 | 你怎么做 |
|---|---|
| 钉死的时刻或次数 (如 "每天 9 点汇总") | 照做, 不按重算结果改定时; 收到 11 仍跑 `hxaioa plan` 让服务端记账, 估算额度撑不到重置时在群里告诉主人一次 |
| 一个频率 (如 "半小时一次", "尽量实时") | 当作高峰期的目标: `hxaioa plan --min-interval <主人说的分钟数>`, 高峰不密于它, 低谷自动放宽; 额度不够时告诉主人要取舍什么 |
| 没提定时 | 按本文自己定 |

## 每天重算 (next 退出码 11)

服务端在宿主时区每天 3 点后第一次触发时要求重算, 一天一次。

1. 读额度: 宿主有额度或用量查询时, 取三项: 总额度已用百分比, 总额度重置时间 (ISO, 带时区), 今日额度已用百分比。拿不到就三项都不给。
2. 运行 `hxaioa plan --pool-used <总已用%> --pool-reset <重置时间> --daily-used <今日已用%>`; 宿主最短间隔不是 10 分钟时加 `--min-interval <分钟>`。
3. 按输出改本任务的定时 (时区按输出): 宿主支持多条 cron 就全用; 只能写一条用 "只能写一条时用" 那行; 只支持 "每 N 分钟" 时取 N = 1440 / 每天次数 (取整, 不小于最短间隔)。
4. `hxaioa me --trigger "<改后的表达式>"`。
5. 和原来不一样时用一句话告诉主人: 每天次数, 高峰间隔, 单次成本; 一样就什么都不发。

改不了自己的定时 (宿主不允许) 时, 把 plan 的结果用一句话发给主人, 请主人改。

## 算法 (服务端算, 这里只为理解输出)

- 单次成本 c: 两次重算之间总额度的涨幅 / 期间触发次数, 最近 14 个样本平均。额度只有整数百分比, 样本越多越准; 还没有样本时按 0.5% 估。
- 每天可用次数: min(剩余总额度 x 0.9 / c / 距重置天数, 剩余今日额度 x 0.9 / c), 留 10% 余量。没给额度时保持现有每天次数。
- 按时段分配: 各小时次数 ∝ sqrt(该小时人发消息的到达率), 总次数固定时这样平均等待最短; 单小时最多 60 / 最短间隔 次。
- 近 14 天历史不足 7 天或消息少于 10 条时均匀分布 (bootstrap), 之后按实际分布 (fitted)。

## 边界

- 闸门省掉的是触发之后的工作, 省不掉宿主启动一个回合本身, 所以每天次数才是额度的大头。
- 事件只看本群人发的消息; 别的群, 网页, 邮件这类来源要实时, 让对应插件把事件发进本群。
