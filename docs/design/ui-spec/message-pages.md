# 消息页: 概念, 页面与省额度 (#121)

设计稿: 画廊 `ChatRoomDemo` `DirectDemo` `GroupInfoDemo` `MembersDemo` `HomeChat` (真实 Compose 渲染), 图在 #121 评论。

## 1. 概念

| 概念 | 是什么 | 存在哪 | 和现在的关系 |
| --- | --- | --- | --- |
| 人 (单聊) | 只能是真人账号; 两个人的私聊 | 复用多人群: channel `dm:<小 uid>:<大 uid>`, 两个成员 | 新增; 现在没有真人私聊 |
| 群 | 一个 `channel`; 真人成员 + Agent | `chat_meta` + `room_member` | 不变 |
| Agent | 永远运行在群里, 不能单聊 | `ChatMeta.agents` | 不变; 服务端拒绝给 `dm:` 群接 Agent |
| 域 | 列表里的一行, 点进去是一组群 (像 QQ 群助手); 一个群只在一个域里 | 账号设置 `chatFolders` (已多端同步) | 存储不变, 从 "筛选条" 改成 "列表里的一行" |
| 标签 | 企业微信式: 人和群都能打多个标签, 列表顶部按标签筛选 | 账号设置新键 `chatTags: { 标签: [channel] }` | 新增, 不加接口 |
| 备忘 | 自己和自己 (本机发的) | 不变 | 列在 "人" 一侧, 置顶 |
| 来源群 | 没写 channel 的推送按来源名成群 | 不变 | 按群显示 (系统发送者头像), 不当作人 |

## 2. 页面

- 消息列表 (顶部标签 "消息"): 只有一列。置顶在最上面, 超过 3 个折叠成 "还有 n 个置顶"; 域是普通的一行 (叠层头像 + "域 · n"), 未读为域内合计; 最上面一排是标签筛选。单聊与群同列, 群带 "n Agent", 单聊不带。
- 群会话 (结构照 QQ 手机版): 顶栏 群名 + "n 人 · m 个 Agent"; 群公告条; 气泡左边头像, 上面身份标签 + 名字; Agent 头像是圆角方块, 气泡描边用它的颜色, 可内嵌任务进度; 系统提示居中; 引用在气泡顶; "正在输入"; 输入栏左边留语音位 (按住说话; 语音输入本是输入法的事, 先不实现), 下一排 表情, 图片, 拍照, 文件, 更多; @ 不占按钮: 输入 "@" 弹出选择 (全体成员, Agent, 真人), 或长按头像直接插入。
- 单聊: 同上, @ 选择里没有 Agent, 顶栏写 "真人 · 在线"。
- 群聊设置 (原 "群设置" 页重做): 头部 (头像, 名字, channel, 域, 群类型) + 计数 (成员, Agent, 今日消息); 成员横排 + 邀请; Agent 列表 (运行中 / 待报到 / 插件); 查找记录, 群文件, 收藏, 精选; 资料 (群名称, 所属域, 群类型, 展示方式); 提醒 (置顶, 免打扰, 显示正在输入); 清空聊天记录, 删除群。
- 成员与 Agent: 两个标签; 搜索; 群主 / 管理员, 成员分组; 在线点; 邀请链接。

现有 `GroupSettingsPage` 的功能 (改头像, 群类型, 清空, 删除, 成员卡, 邀请) 全部保留, 只换布局。

## 3. 每个元素的数据从哪来 (请求数)

| 元素 | 来源 | 打开页面时的请求 |
| --- | --- | --- |
| 群名, 头像, 域, 群类型, 计数 (成员数, Agent 数) | 已缓存的 `GET /chats` (ETag) 里的 `ChatMeta` | 0 |
| Agent 列表与状态 | `ChatMeta.agents` (`joined` `pending` `active` `plugin`) | 0 |
| 今日消息数, 总览 "今日脉搏" | 本地消息库按天聚合 | 0 |
| 查找记录 | 本地消息库 | 0 |
| 域与域内未读 | 设置 `chatFolders` + 本地未读 | 0 |
| 群公告 | 建议新字段 `ChatMeta.notice` (≤500 字), 随群列表下发 | 0 |
| 成员列表 | `GET /chats/{c}/members`, 本地缓存先显示 | 1 (建议加 ETag 后多为 304) |
| 成员头像 | 建议 `RoomMember.avatar` (头像 id), 图片按 id 永久缓存 | 0 (除首次图片) |
| 在线状态 | 长连接 presence 帧 | 0 |
| 群文件 | 群历史里带附件的消息 (`data.file`), 本地库筛; 更早的按需翻页 | 0 (翻到本地没有的才请求) |

## 4. 现有实现里查到的浪费 (按影响排序)

1. 已读位置写在 `chat_meta` 行里: 每次 `PATCH read` 都改 `updated`, 群列表 ETag 变, 再广播 `chat_sync`, 所有在线设备整表重拉 `GET /chats`。一次已读 = 1 写 + 每台设备 1 次整表读与下载。
2. Agent 活跃时间 (`markActive`, 每 2 分钟一次): `replaceChat` 不改 `updated`, ETag 不变, 却广播 `chat_sync`; 各端拉到 304, 新的 `active` 永远到不了客户端 (显示会旧), 还白花每台设备一次请求。另外每次都扫全部 `chat_meta` 找这把 key。
3. `GET /chats` 算 ETag 要先读出全部群并逐行组装视图, 304 也照样全读。
4. `GET /chats/{c}/members` 没有 ETag, 每次打开都全量。

## 5. 改法 (都向后兼容: 旧客户端忽略新字段, 仍可整表重拉)

- 已读拆表: `chat_read (channel, uid, seq)`; 推 `{ t: "chat_read", channel, read }` 帧带值, 各端本地更新, 不碰群列表 ETag, 不触发重拉。
- 活跃时间进内存: DO 里按 keyId 记 `active`, 随 presence 帧推给在线端; 落库最多每 30 分钟一次 (或和 cron 合并); keyId → channel 建内存索引, 不再扫全表。
- `chat_sync` 帧带上变化的那一行 `ChatMeta` (`chat` 字段), 新客户端直接合并, 不再 `GET /chats`; 冷启动仍走 ETag。
- 群列表版本号: 任何群资料改动时版本 +1 (存一行或内存 + 启动时恢复), ETag 直接用它, 304 不读表。
- 成员列表加 ETag (成员数 + 最近加入 / 改角色时间), 客户端缓存。
- 单聊复用多人群: 不加新表; `ChatMeta.kind = "dm"` (不写为群), 对方 uid 从 channel 解析。
- 群公告进 `ChatMeta`, 不单独开接口。
- 成员列表现在不带头像: 本人头像 id 同时写进用户表, 成员列表直接带出, 不用逐个读设置。

## 6. 兼容性检查

| 新功能 | 原功能 | 结论 |
| --- | --- | --- |
| 消息改为顶部标签 | 底部五栏里的 "消息" | 底栏去掉; `pages.json` 改入口后跑 `gen.py` 同步入口表与 `TabNavTest`; 返回规则见 `docs/client/android/navigation.md` |
| 域 | 组 `chatFolders` | 同一份数据, 只改名; 老版本看到的仍是组 |
| 单聊 | 多人群, 邀请, 角色 | 复用; `dm:` 群不允许邀请第三人, 不允许接 Agent, 没有群主 / 管理员 |
| 单聊的可见性 | 母号能读全部群 | 母号就是服务端, 能看到所有私聊; 设置页与单聊顶栏需写明 |
| 群公告 | 无 | 新增可选字段, 旧端忽略 |
| Agent 在群里 | `POST /chats/{c}/agents` | 不变 |
| 来源群 (无 channel) | 按来源名成群 | 继续按群显示, 不当成 "人" |
| 总览 v2 的 "需要我 / 正在发生 / 值得一看" | 服务端 `buildOverview` 三层 | 直接用三层, 不加接口 |
| 总览 v2 的提交热力格 | GitHub 日报卡 | 需要按天提交数; 建议 cron 时算好存一行, 总览只读这一行 |

## 7. 成员数量: 架构上不设上限

现状 (单个 Hub DO, SQLite):
- 消息每条只存一份, 不按成员复制收件箱; 已读只是每人一个位置。成员多少都不增加每条消息的写入。
- 长连接用 Hibernation (`acceptWebSocket`), 空闲连接不计费; 推送按在线连接过一遍, 只发给群成员。
- 成员表 `room_member (grp, member)` 行数没有上限。

会随人数变成瓶颈的地方 (要改):
- `GET /chats/{c}/members` 一次返回全部: 改成游标分页 + 搜索, 群资料页只取前 10 个头像; 人数用 `ChatMeta.members`。
- `roomsOf(uid)` 按 `member` 查, 主键是 `(grp, member)`, 走全表: 加 `member` 索引。
- 群资料变化的 `chat_sync` 发给所有在线端, 不分群: 改成只发给该群成员。
- 推送时每个连接都判断一次受众: 改成按群维护在线连接集合 (内存), 只遍历该群。

天花板与再往上: 整个服务端是一个 DO, 吞吐与存储受单个 DO 限制。真要到那个量级, 按群拆成每群一个 DO (消息, 成员, 在线连接都在群 DO 里), Hub 只管账号与路由。接口 (分页成员, 计数在群资料, 帧带增量) 现在就按这个设计, 将来拆分客户端不用改。

## 8. 消息操作与 Agent 怎么看到

| 操作 | 界面 (对齐 QQ) | 存储 | Agent 看到的 |
| --- | --- | --- | --- |
| 长按 | 气泡上方两排: 复制, 转发, 收藏, 回复 / 多选, 精选, 撤回, 删除 | 无 | 无 |
| 回复 | 气泡顶部引用条, 点了跳原消息 | 已有 `reply` 快照 (200 字) | 原样带引用快照 |
| 撤回 | 自己 2 分钟内, 管理员随时; 原位置留 "xx 撤回了一条消息" | 已有墓碑 (`recall.ts`) | 推墓碑; 指令要求它忘掉那条, 已基于它做的事不回滚 |
| 删除 | 只删自己这边 (本地), 管理员可删全员 | 已有 `delete` 墓碑 | 全员删除同撤回; 本地删除它看不到变化 |
| 逐条转发 | 每条变成一条新消息 | 已有 `fwd` | 普通消息, 带 "转自" |
| 合并转发 | 一张 "聊天记录" 卡片: 来源群, 前 4 条摘要, 共 n 条; 点开是只读的小会话页 | 新: 一条消息, `data.bundle = { from, count, refs: [seq], head: [前 4 条摘要] }`, 不复制正文 | 懒加载: 先只给卡片 (标题, 摘要, 条数), 指令里写明需要细节时按 `refs` 调 `GET /events/seq/{seq}` (或一次性 `?seqs=` 批量) 展开; 原消息被撤回的显示 "已撤回" |
| 收藏 | 已有 | 已有 (按引用) | 无 |
| 精选 | 收录到日报 / 周报群 | 已有 | 精选 Agent 正常读 |

## 9. 头像

- 点头像: 底部资料卡。真人: 身份, 群昵称, 入群时间, 最近发言, 共同群; 发消息 (单聊), @TA; 群主 / 管理员多出设管理员, 移出。Agent: 状态, 版本, 还能读的群, 最近活跃, 接入者; @它, Agent 设置 (没有 "发消息", Agent 只在群里)。
- 长按头像: 直接在输入框插入 "@名字 "。
- 数据: 都来自群资料缓存与成员缓存, 打开不请求; "最近发言, 本群条数" 本地库算。

## 10. Agent 设置页 (按 #117 定论)

云 Agent 靠 skill 干活, 记忆在它自己那边 (我们不维护), 触发方式由它用 `hxaioa me --trigger` 上报。主人能改的只有三项, 其余只读。

| 项 | 来源 | 可改 |
| --- | --- | --- |
| 名字 | `name` | 是 |
| 可读的群 | `reads` | 是 |
| 触发方式, 下次触发, 今天还有几次 | `trigger` (cron 或间隔 + 时区), `nextRuns` | 否 (Agent 上报) |
| 上次运行, 待处理 | `lastRun`, 处理游标 | 否 |
| 已装 skill 与应有版本, 小更新 / 大更新缺失 | `skills`, `X-Aioa-Want`, 插件 `changes` | 否 |
| 命令行版本 | `client` `version` | 否 |
| 大更新自动执行 | `autoMajor` (拨开要重发一次接入语) | 是 |
| 复制接入语, 重新接入 | 接入语, `rotate` | 操作 |
| 移出本群 | `DELETE .../agents/{keyId}` | 操作 |

资料卡上 Agent 显示: 状态, skill 与命令行版本, 所在与可读的群, 触发与下次时间, 接入者; 按钮 "@它" 与 "Agent 设置"。

## 11. 展示方式 (群怎么显示)

现在 `ChatMeta.view` 有 `chat` (聊天), `mail` (邮件), `feed` (信息流)。改成可扩展的 "视图":

- 视图 = 同一份群消息的另一种排法, 不另存数据。`view` 是字符串 id, 客户端按 id 找渲染器, 不认识的 id 回落成聊天并提示 "需要新版 App 或插件"。
- 内置: `chat` 聊天, `feed` 信息流 (今天 / 全部 / 收藏), `mail` 邮件 (只读, 不能切走)。
- 候选: `board` 看板 (按待办状态分列, 点子待办用), `timeline` 时间线 (日报, 部署记录, 只看卡片不看闲聊), `gallery` 相册 (只看图片与文件, 也就是群文件)。
- 插件提供视图: 插件清单声明 `views: [{ id, title, from: "feed" | "board" | "timeline", map }]`, 只能组合内置视图并给出字段映射 (插件不能下发原生代码); 群设置 "展示方式" 里列出可选的。
- 一个群可以有主视图 + 若干副视图 (顶栏右上切换), 例如开发群主视图聊天, 副视图看板。
- 发消息的约束跟着视图走 (现有 `feed-guard`: 信息流群拒收 HTML), 新视图同样在服务端声明约束。
