# 消息页: 概念, 页面与省额度 (#121)

设计稿: 画廊 `ChatRoomDemo` `DirectDemo` `GroupInfoDemo` `MembersDemo` `HomeChat` (真实 Compose 渲染), 图在 #121 评论。

## 1. 概念

| 概念 | 是什么 | 存在哪 | 和现在的关系 |
| --- | --- | --- | --- |
| 人 (单聊) | 只能是真人账号; 两个人的私聊 | 复用多人群: channel `dm:<小 uid>:<大 uid>`, 两个成员 | 新增; 现在没有真人私聊 |
| 群 | 一个 `channel`; 真人成员 + Agent | `chat_meta` + `room_member` | 不变 |
| Agent | 永远运行在群里, 不能单聊 | `ChatMeta.agents` | 不变; 服务端拒绝给 `dm:` 群接 Agent |
| 域 | 几个群收成一组 (TG 文件夹) | 账号设置 `chatFolders` (已多端同步) | 只改名与入口, 存储不变 |
| 备忘 | 自己和自己 (本机发的) | 不变 | 列在 "人" 一侧, 置顶 |
| 来源群 | 没写 channel 的推送按来源名成群 | 不变 | 按群显示 (系统发送者头像), 不当作人 |

## 2. 页面

- 消息列表 (顶部标签 "消息"): 上面一排是域 (全部, 各个域, 未读), 下面 TG 式会话列表, 单聊与群同列; 群带 Agent 标签, 单聊不带。
- 群会话 (结构照 QQ 手机版): 顶栏 群名 + "n 人 · m 个 Agent"; 群公告条; 气泡左边头像, 上面身份标签 + 名字; Agent 头像是圆角方块, 气泡描边用它的颜色, 可内嵌任务进度; 系统提示居中; 引用在气泡顶; "正在输入"; 输入框下一排功能钮 (语音, 图片, 拍照, @, 交给 Agent, 表情, 更多)。
- 单聊: 同上, 没有 @ 和 Agent 钮, 顶栏写 "真人 · 在线"。
- 群聊设置 (原 "群设置" 页重做): 头部 (头像, 名字, channel, 域, 群类型) + 计数 (成员, Agent, 今日消息); 成员横排 + 邀请; Agent 列表 (运行中 / 待报到 / 插件); 查找记录, 群文件, 收藏, 精选; 资料 (群名称, 所属域, 群类型, 展示方式); 提醒 (置顶, 免打扰, 显示正在输入); 清空聊天记录, 删除群。
- 成员与 Agent: 两个标签; 搜索; 群主 / 管理员, 成员分组; 在线点; 邀请链接。

现有 `GroupSettingsPage` 的功能 (改头像, 群类型, 清空, 删除, 成员卡, 邀请) 全部保留, 只换布局。

## 3. 每个元素的数据从哪来 (请求数)

| 元素 | 来源 | 打开页面时的请求 |
| --- | --- | --- |
| 群名, 头像, 域, 群类型, 计数 (成员数, Agent 数) | 已缓存的 `GET /chats` (ETag) 里的 `ChatMeta` | 0 |
| Agent 列表与状态 | `ChatMeta.agents` (`joined` `pending` `active` `plugin`) | 0 |
| 今日消息数, 总览 "今日脉搏" | 本地消息库按天聚合 | 0 |
| 查找记录 | 本地消息库 | 0 |
| 域与域内未读 | 设置 `chatFolders` + 本地未读 | 0 |
| 群公告 | 建议新字段 `ChatMeta.notice` (≤500 字), 随群列表下发 | 0 |
| 成员列表 | `GET /chats/{c}/members`, 本地缓存先显示 | 1 (建议加 ETag 后多为 304) |
| 成员头像 | 建议 `RoomMember.avatar` (头像 id), 图片按 id 永久缓存 | 0 (除首次图片) |
| 在线状态 | 长连接 presence 帧 | 0 |
| 群文件 | 待核实是否已有按群列文件的接口 | 待定 |

## 4. 现有实现里查到的浪费 (按影响排序)

1. 已读位置写在 `chat_meta` 行里: 每次 `PATCH read` 都改 `updated`, 群列表 ETag 变, 再广播 `chat_sync`, 所有在线设备整表重拉 `GET /chats`。一次已读 = 1 写 + 每台设备 1 次整表读与下载。
2. Agent 活跃时间 (`markActive`, 每 2 分钟一次): `replaceChat` 不改 `updated`, ETag 不变, 却广播 `chat_sync`; 各端拉到 304, 新的 `active` 永远到不了客户端 (显示会旧), 还白花每台设备一次请求。另外每次都扫全部 `chat_meta` 找这把 key。
3. `GET /chats` 算 ETag 要先读出全部群并逐行组装视图, 304 也照样全读。
4. `GET /chats/{c}/members` 没有 ETag, 每次打开都全量。

## 5. 改法 (都向后兼容: 旧客户端忽略新字段, 仍可整表重拉)

- 已读拆表: `chat_read (channel, uid, seq)`; 推 `{ t: "chat_read", channel, read }` 帧带值, 各端本地更新, 不碰群列表 ETag, 不触发重拉。
- 活跃时间进内存: DO 里按 keyId 记 `active`, 随 presence 帧推给在线端; 落库最多每 30 分钟一次 (或和 cron 合并); keyId → channel 建内存索引, 不再扫全表。
- `chat_sync` 帧带上变化的那一行 `ChatMeta` (`chat` 字段), 新客户端直接合并, 不再 `GET /chats`; 冷启动仍走 ETag。
- 群列表版本号: 任何群资料改动时版本 +1 (存一行或内存 + 启动时恢复), ETag 直接用它, 304 不读表。
- 成员列表加 ETag (成员数 + 最近加入 / 改角色时间), 客户端缓存。
- 单聊复用多人群: 不加新表; `ChatMeta.kind = "dm"` (不写为群), 对方 uid 从 channel 解析。
- 群公告进 `ChatMeta`, 不单独开接口。
- 成员列表现在不带头像: 本人头像 id 同时写进用户表, 成员列表直接带出, 不用逐个读设置。

## 6. 兼容性检查

| 新功能 | 原功能 | 结论 |
| --- | --- | --- |
| 消息改为顶部标签 | 底部五栏里的 "消息" | 底栏去掉; `pages.json` 改入口后跑 `gen.py` 同步入口表与 `TabNavTest`; 返回规则见 `docs/client/android-navigation.md` |
| 域 | 组 `chatFolders` | 同一份数据, 只改名; 老版本看到的仍是组 |
| 单聊 | 多人群, 邀请, 角色 | 复用; `dm:` 群不允许邀请第三人, 不允许接 Agent, 没有群主 / 管理员 |
| 单聊的可见性 | 母号能读全部群 | 母号就是服务端, 能看到所有私聊; 设置页与单聊顶栏需写明 |
| 群公告 | 无 | 新增可选字段, 旧端忽略 |
| Agent 在群里 | `POST /chats/{c}/agents` | 不变 |
| 来源群 (无 channel) | 按来源名成群 | 继续按群显示, 不当成 "人" |
| 总览 v2 的 "需要我 / 正在发生 / 值得一看" | 服务端 `buildOverview` 三层 | 直接用三层, 不加接口 |
| 总览 v2 的提交热力格 | GitHub 日报卡 | 需要按天提交数; 建议 cron 时算好存一行, 总览只读这一行 |
