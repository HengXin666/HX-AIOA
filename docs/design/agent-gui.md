# Agent GUI 方案 (#126)

在 HX-AIOA 里驱动主机上的编程 Agent: 以后所有会话都从这个 GUI 开 (桌面, Web, 安卓), 它就是我们自己的 t3code。本文是架构, 界面见 [agent-gui-ui.md](agent-gui-ui.md)。讨论稿, 结论以 #126 评论为准。

## 0. 已定 (11-27)

| 项 | 结论 |
| --- | --- |
| 协议 | 所有 Agent CLI 走 ACP。我们要的是各家 Harness 的 agent loop, 用 ACP 自由组合 "Agent CLI x 模型", 订阅模型 (如 Antigravity 这类不能带出去的) 只能这样用 |
| 主机端 | 放进探针 (`probe-agent.mjs`, 与终端同一套安装和 key) |
| 会话从哪开 | 只从 GUI 开; 普通终端里开的 CLI 不在本方案内 |
| 工作台 | 功能对标 t3code / t3code-enhancer / Orca, 照搬 |
| 审批模式 | 自己设计 (第 5 节) |
| 统计 | 要实时 tok/s, 缓存命中, 上下文占用 (第 4 节) |
| DSH | 用社区 `@openma/deepseek-harness-acp` (11-27) |
| 隧道 | CF 侧由用户自己配置 (自己的命名隧道与主机名, 或 quick tunnel 随机子域名), 探针只负责跑 cloudflared 与上报地址 (11-27) |
| 配置存哪 | Agent 实例, 审批规则, 路线, 设备列表等全部存在探针本地, 客户端经直连读写, 不经过 Hub, 省额度 (11-27) |
| 电脑前看着时 | 默认仍推手机但静默 (无声无震动), 电脑上答了就撤回消失; 可在设置里改 (11-27, 见 5.4) |

设计目标按优先级: 1. 请求尽可能少; 2. CF 额度尽可能少; 3. 尽可能实时, 高性能; 4. 尽可能无损, 原生体验。

## 1. 从 t3code 拿什么

t3code 已经把这件事做完了一遍 (MIT), 我们按它的结论来, 只把 "服务端" 换成探针, 把 "T3 Connect" 换成我们的 Hub:

| t3code 现成的 | 我们怎么用 |
| --- | --- |
| 执行只在拥有工作区的机器, 客户端只遥控, 远程客户端不能拿自己的文件系统或凭据顶替 | 同 |
| T3 Connect: 中转 Worker 只发凭据, HTTP 与 WS 直接走主机的隧道域名, Worker 不在数据路径上 | 同: Hub 只发配对凭据与转审批, 工作模式直连探针 (第 2 节) |
| ACP Registry: 从官方目录装 Agent, 放 `<home>/tools/<id>/<版本>/`, sha256 校验, 后台查更新; 也可填本地 ACP 命令 (如 `dsh --profile acp`) | 同, 装在探针目录下 |
| Provider instance: 同一种 Agent 可配多个实例, 各自环境变量与凭据, 互不共享状态 | "Agent 实例" (第 3 节) |
| 模型, 斜杠命令, `$` 技能, 原生会话导入, 认证方式都由 Agent 通过 ACP 报上来 | 同, 界面不写死任何厂商 |
| ACP 先协商 v2 预览, 不行退 v1 | 同 |
| 权限模式不伪造, 原生选项 id 透传, 每个请求都能拒绝; 待审批时直接打字 = 拒绝并把话带给 Agent | 同, 审批卡 "拒绝并说明" 就是这个 |
| 适配器陷阱: 配置延迟公布, `Default` 是哨兵不是模型 id, 太早 Stop 会卡死会话 (要等 turn 开始信号), 任何结束路径都要收尾未决请求, 额度错误归类为 `usage_limit` 带重置时间 | 写进探针的 ACP 客户端 |
| checkpoint 用隐藏 git ref, 不往用户分支加提交; Agent 不能回滚对话时拒绝回退文件 | 同 (第 2 阶段) |
| 每个会话可用独立 worktree | 同 |
| 线上预算: 冷启动, 翻历史, 补帧都有字节与行数上限; 快照不带工具原始输出; 命令输出不进事件流, 展开那一行才订阅 | 同, 这是性能与流量的关键 |
| 客户端连接运行时: 每个环境一个连接主人, 唯一的重试者, 带抖动的指数退避; 回前台先探活, 探活失败才换 socket; 传输健康与数据新鲜分开显示 | Web 与安卓各实现一份, 行为一致 |
| 路线只是提示: 先验证对端是预期的环境再发凭据, HTTPS 配对的令牌不降级到 HTTP | 同 |

不拿: Effect 全家桶, 事件溯源 + 发件箱 (我们先用 Agent 自己的会话存档 + 探针的原始 ACP 日志), Clerk, Electron。

## 2. 架构与路线

```
                 配对 / 路线 / 审批 (很少的消息)
   客户端  <------------------------------------>  Hub DO  <--- 探针已有长连 --->  探针
     |                                                                             |
     |  工作模式数据: ACP 原样 (WS)                                                 |- ACP 客户端 x N 个 Agent 进程
     '-------- 本机 127.0.0.1 / 局域网 / CF Tunnel (不经过 Worker 与 DO) ----------'|- 原始 ACP 日志 (回放, 补帧)
                                                                                   '- git / 文件 / PTY 终端
```

### 2.1 三条路线, 按顺序试

| 路线 | 何时 | CF 额度 | 延迟 |
| --- | --- | --- | --- |
| 本机 `127.0.0.1:<端口>` | 桌面端或浏览器就在这台主机上 | 0 | <5 ms |
| 局域网 `<内网地址>:<端口>` | 手机和主机同一 Wi-Fi | 0 | ~10 ms |
| CF Tunnel `agent-<主机>.<你的域名>` | 在外面 | 0 (Tunnel 流量不算 Worker / DO 请求) | 30-80 ms |
| Hub 中继 (兜底) | 主机没配隧道 | 按 v1 估算: 输出中 1 小时约 900 次计费请求 + DO 时长 | 同隧道 |

- 隧道的 CF 侧由用户自己配置: 贴自己命名隧道的 token 并填主机名, 或用 quick tunnel 的随机子域名 (地址每次启动会变, 探针变了就重报给 Hub)。探针只负责跑 cloudflared (复用 hxoa 的 HTTP/2 + fake-ip 绕过) 与上报地址, 不替用户建 DNS。
- 隧道主机名不要挂 Worker 路由, 否则流量会算 Worker 请求。
- 客户端缓存上次成功的路线, 下次直接用; 失败才按顺序重试, 路线列表只在失败时向 Hub 重取。连上后先验证主机身份 (主机公钥签名), 再发设备凭据。
- 浏览器从 https 页面连 `127.0.0.1`: 探针要回 `Access-Control-Allow-Private-Network` 等私有网络访问头。

### 2.2 配对与认证 (只经过 Hub 一次)

1. 主账号在 App 里点 "配对这台主机", 输密码 (复用终端票据, 5 次错锁 5 分钟)。
2. 客户端生成设备密钥对, Hub 经探针长连把公钥与票据转给探针 (约 2 条 DO 消息)。
3. 探针登记设备, 回主机公钥与路线列表 (同样经 Hub)。
4. 之后每次连接: 客户端直连探针, 用设备私钥签挑战, 不再经过 Hub。吊销: App 里删设备 (经 Hub 一条消息) 或在主机上删。

Hub 看不到会话内容, 也拿不到能直连探针的凭据 (只有公钥经过它)。

### 2.3 探针: ACP 多路代理

- 每个会话一个 Agent 子进程 (或一个进程多会话, 看 Agent), 探针是唯一的 ACP 客户端。
- **无损**: 客户端拿到的就是原始 ACP 消息 (JSON-RPC 原文), 只外包一层 `{sid, seq, m}`; 探针另加少量 `hx/*` 方法 (git, 文件, 终端, 统计, 设备)。ACP 加了新能力, 客户端渲染器跟上就能用, 探针不用改。
- **多端同看**: 多个客户端可同时附着一个会话; 权限请求先答先得, 其它端收到撤回。
- **回放**: 探针把每个会话的 ACP 消息追加写进本地日志 (JSONL + 每轮的偏移索引)。客户端附着时只取最近窗口 (如最近 3 轮且不超过 256 KB), 往上翻按轮分页; 断线按 `seq` 补。工具原始输出与终端输出不进窗口, 展开才取。
- **合批**: 探针按 16 ms 合批发送 (一帧一包), WS 开 permessage-deflate。流式文本是增量, 不重发全文。
- Agent 进程与会话在客户端全部断开后继续跑; 跑完或等审批时按第 5 节通知。

### 2.4 Hub 里只剩什么

| 内容 | 落库 | 频率 |
| --- | --- | --- |
| 主机路线列表, 设备公钥登记 | 是 (很小) | 配对与改路线时 (quick tunnel 地址变了也要重报) |
| 会话索引 (标题, 状态, 上下文占比) | 否, 只放 DO 内存, 探针重连时重报 | 状态变化时, 5 秒合并 |
| 待审批卡片 | 是 (离线手机要能补到) | 见第 5 节 |

### 2.5 请求账 (每天: 100 轮, 200 次审批, 工作模式 3 小时)

| 场景 | Worker 请求 | DO 消息 (WS 入站按 20:1 计费) | 行写入 |
| --- | --- | --- | --- |
| 工作模式 3 小时 (直连) | 0 | 0 | 0 |
| 会话索引 (每轮约 2 次状态变化) | 0 | 约 200 | 0 |
| 审批 (每次都经 Hub, 见 5.4) | 0 | 200 x 3 = 600 | 200 |
| 合计 | 0 | 约 800 条, 计费约 40 次 | 约 200 |

对照免费额度 (DO 请求 10 万, 行写入 10 万 / 天): 可以忽略。没有隧道走中继时, 工作模式那一行按 2.1 的兜底估算。

## 3. Agent 与模型组合

- **Agent 实例** = ACP 启动命令 + 参数 + 环境变量 + 显示名 + 默认模型 / 模式 / 思考深度。来源: ACP Registry 一键装, 或本地命令。同一个 Agent 可建多个实例 (例: Claude Code 订阅版, Claude Code 接第三方兼容接口版)。
- **模型** 由 Agent 在 ACP 配置选项里报上来; 支持自定义模型 id。会话中途换模型 = `session/set_config_option`, 下一步生效。
- **跨 Agent 接力**: 会话菜单 "交给另一个 Agent": 用当前会话的摘要 + 改动列表在新 Agent 上开新会话 (t3code 的 "可移植上下文交接"), 两个会话互相链接。
- 凭据只在 Agent 自己的存储里; 登录用 ACP 的认证方式 (浏览器登录在你当前设备打开链接, 终端登录在探针 PTY 里跑)。

常用 Agent (都用 ACP):

| Agent | 启动 |
| --- | --- |
| Claude Code | `claude-agent-acp` (Registry) |
| Codex | `codex-acp` (Registry) |
| DSH | 官方 `dsh --profile acp` 只做自动化 (无计划, 思考, 终端, 用量); 工作台用社区 `@openma/deepseek-harness-acp`, 或自写 dsh 插件 |
| Antigravity, Cursor, Grok, OpenCode, Gemini CLI 等 | Registry 里有就一键装 |

## 4. 实时统计

| 指标 | 来源 | 实时性 |
| --- | --- | --- |
| 上下文占用 | ACP `usage_update` 的 `used / size` (已稳定) | 每步 |
| 累计费用 | `usage_update.cost` (可选) | 每步 |
| 缓存命中率 | 每轮结束 `usage` 的 `cachedReadTokens / (输入 + 缓存读 + 缓存写)` (草案字段) | 每轮; 轮内显示上一轮 |
| tok/s | ACP 没有, 探针估算: 消息与思考增量按字数估 token, 只计活跃输出时间 (剔除首字等待与工具间隙); 轮末用 `outputTokens / 活跃时长` 校准, 并记下该模型的估算系数 | 每秒 |
| 逐步精确值 (可选) | 约定 `_meta` 命名空间 `hx.aioa/step`: 每次模型调用 `{input, output, cacheRead, cacheWrite, ms}`。自写的 dsh 插件一定带, 其它不改上游 | 每步 |
| 5h / 7d 额度 | ACP 没有, 先不做 | |

统计由探针算好, 作为 `hx/stats` 每秒最多一帧, 只发给附着了该会话的客户端, 走直连, 不占 CF。

## 5. 审批模式

工作模式照搬; 审批模式的目标: **10 秒内在手机上做对一个决定, 不漏, 不吵。**

### 5.1 一张卡回答四个问题

| 问题 | 卡上写什么 | 来源 |
| --- | --- | --- |
| 它想干什么 | 动作一句话 + 原样内容 (命令全文, diff 前两段, 网址) | ACP `ToolCall` 的 `kind` `title` `content` `locations` |
| 为什么 | 这一轮你的原话 (2 行) + Agent 最后一段话 (3 行) | 探针的 ACP 日志 |
| 影响多大 | 风险档与理由, 目录与分支, 本轮已改文件数 | 探针规则 |
| 我能怎么答 | Agent 原生选项 (允许一次 / 总是允许 / 拒绝 ...) + "拒绝并说明" + "看全部" | ACP `PermissionOption` |

卡片内容由探针算好 (几百字节), 手机不需要全文。

### 5.2 风险档 (只决定在哪答, 不替你答)

| 档 | 例子 | 怎么答 |
| --- | --- | --- |
| 低 | 读, 搜索, 工作区内改文件, 跑测试 / 构建 / lint | 通知栏按钮直接答 |
| 中 | 装依赖, 联网下载, 写工作区外, `git commit` | 点进卡片 |
| 高 | 删除, `git push --force`, `sudo`, 碰密钥 / `.env` / `~/.ssh`, 重启服务 | 点进卡片, 长按确认 |

没有 "自动放行" 规则: 想少被问就用 Agent 原生的 "总是允许" 或切权限模式 (Agent 公布的模式原样显示)。

### 5.3 收件箱

- 按 "Agent 因此停了多久" 排序; 同会话的挤在一起, 只露最前一张, 写 "还有 n 个"。
- 同会话连续同类低风险请求合成一张, 一次答完 (回 Agent 时仍逐个回答)。
- 答复后 5 秒内可撤销 (还没发给 Agent 时)。
- 也推这些关键时刻: 一轮做完 (总结, 改动, 用时, token 与缓存命中), 计划待批, Agent 提问, 出错 / 额度用尽 (带重置时间), 上下文超过 80%。

### 5.4 电脑前看着时手机怎么办 (11-27 定: 默认静默推, 答了就消失)

- 每个请求都发 `as_req` 给 Hub (一次审批约 3 条 DO 消息, 量很小), 探针在帧里带 `quiet`: 有客户端在前台附着这个会话时为真。
- `quiet` 为真: 手机只进收件箱并发一条静默通知 (无声无震动, 不亮屏); 电脑上答了, `as_unreq` 撤回, 手机上的卡片与通知一起消失。
- `quiet` 为假 (没人在看): 正常推送 (有声)。
- 静默推送 60 秒后还没人答 (你可能离开了电脑): 探针把同一请求改成正常推送再发一次。
- 任一端答了, 其它端立即撤回 ("已在电脑上处理")。5 分钟没答再推一次, 之后只留红点; 免打扰时段只推高风险。
- 设置 "电脑前看着时手机": 静默推送 (默认) / 不推 / 正常推送; 存在探针本地。

审批在 Hub 里复用现有 Agent 任务模型: `as_req` = `task wait`, `as_answer` = `act`, `as_unreq` = #57 的撤回; 幂等, 二次确认, 离线排队, 推送都现成。

## 7. 安全

- key 需 `probe:agent`; 主机本地开关 `AIOA_AGENT=1`; 只有主账号能配对, 配对要密码。
- 直连只认已配对设备的签名; 隧道只暴露探针的 Agent 端口, 不暴露 shell 以外的东西 (终端仍走原来的三道门)。
- 子进程环境清掉 `AIOA_TOKEN`; Agent 凭据只在主机。
- Hub 不存会话内容; 待审批卡片答复后 24 小时清理。
